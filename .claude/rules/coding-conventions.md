# Coding Conventions — GalSen IA

## Language Rules
- All code comments must be written in **French**.
- User-facing text (UI, messages, documentation for users) must be in **French**.
- Technical documentation, file names, folder names, commit messages and prompt files must be in **English**.

## General Rules
- Prefer simple and readable code over clever code.
- Always write clear and meaningful names (variables, functions, classes).
- Avoid deep nesting when possible.
- Keep functions small and focused on one responsibility.
- Never hardcode secrets or API keys.

## Python-Specific Rules
- Follow PEP 8 style guide for code layout.
- Use snake_case for variable and function names.
- Use CapWords (PascalCase) for class names.
- Use UPPER_CASE with underscores for constants.
- Use type hints for function signatures and return types.
- Use f-strings for string formatting (Python 3.6+).
- Use pathlib for file path operations when appropriate.
- Use virtual environments for dependency isolation.
- Write docstrings for all public modules, functions, classes, and methods.
- Use absolute imports within the project.

## Comments
- Write comments in French.
- Explain the "why", not only the "what".
- Keep comments up to date when code changes.
