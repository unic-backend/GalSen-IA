# GalSen IA v0.1.0 — prototype

First named point in the project's history. It exists so there is something to roll
**back to** — until now the platform had zero tags, and a rollback target that does not
exist is not a rollback plan.

`__release_type__` is `prototype`, and this release is marked as a pre-release. That is
not modesty: the platform's headline capability — text generation — answers `503` until
an operator configures a model provider. Everything below is written so that what is
proven and what is not are told apart.

## What this release contains

**A working API.** 66 routes across the engines (memory, models, knowledge, workflows,
tools, search, notifications, connectors), with RBAC by API key, per-subject data
isolation (ADR-010), rate limiting, threat detection, security headers and health
endpoints.

**Persistence that survives a restart.** `GALSEN_STORAGE_BACKEND=sqlite` puts memory,
models, knowledge, files, notifications, calendar, e-mail and cloud state in
`GALSEN_DATA_DIR`, in WAL mode, with database files restricted to their owner.
`scripts/backup.py` takes a consistent hot backup with `VACUUM INTO` and restores it.

**A deployment that terminates TLS.** `docker compose up` starts Caddy in front of the
application: certificates, renewal and the HTTP→HTTPS redirect are handled, and the
application publishes no port of its own (ADR-012).

**One authoritative instance, enforced.** The application takes an exclusive lock on its
data directory at startup; a second instance on the same directory refuses to start
(ADR-013).

**A build that can be repeated.** Dependency versions are pinned exactly, the test
tooling no longer ships in the production image, and `.github/workflows/release.yml`
rebuilds and starts the image from the tag alone before anything is published.

**2170 tests**, 7 skipped.

## What is not proven, and by whom

| Not proven | Who closes it |
|---|---|
| Text generation end to end | The operator: `ollama serve` with a model whose context is ≥ 8192, or a hosted key. `tests/test_generation_end_to_end.py` skips until then and runs the moment a provider answers — exit criterion **C1** |
| The production image builds and starts | The `Release` workflow, on this tag. It was not verified on the machine that prepared the release: no Docker there, and a check that cannot run is reported, never ticked |
| HTTPS reaches the application through Caddy | The operator, on a host with a domain pointing at it — **TEST 2** |
| The rollback works against a running deployment | The operator, following `docs/deployment/rollback.md` — **TEST 6** |
| The knowledge base is useful | Nobody yet: it holds 0 items. The retrieval, ranking and governance are built and retrieving from nothing |

## Known limitations

- **A key revocation does not survive a restart.** `POST /auth/keys/{fingerprint}/revoke`
  answers `persistent: false` for this reason. Removing the key from `GALSEN_API_KEYS`
  and restarting is the only definitive gesture (ADR-013).
- **No horizontal scaling.** One instance is a decision, not an accident, and it is now
  enforced. ADR-013 records the trigger that would reverse it.
- **Identities are asserted, not verified.** Whoever writes `GALSEN_API_KEYS` states who
  each key belongs to and nothing checks it (ADR-010).
- `flock` and SQLite both assume a local disk. On a network mount neither guarantee holds.

## Upgrading

Nothing to upgrade from — this is the first release.

## Rolling back to this release

`docs/deployment/rollback.md`. The short version:

```bash
git checkout v0.1.0
docker compose build && docker compose up -d
```

Data is not rolled back by that command. If the schema changed between versions, restore
a backup taken before the upgrade — `python scripts/backup.py lister`.
